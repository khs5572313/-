# 정밀 판독기 (docread)

흐린 스캔본이나 휴대폰 사진으로 받은 **생기부·시험지**를 판독하는 도구입니다. 같은 페이지를 두 번 독립적으로 읽고, 결과를 대조하고, 양식 규칙으로 검증해서 **틀릴 수 있는 곳만 사람에게 보여 주는** 방식입니다.

## 왜 이렇게 설계했나

| 흔한 실패 원인 | 이 도구의 대응 |
|---|---|
| A4 한 장을 통째로 AI에 넣으면 내부에서 축소돼 작은 글씨가 뭉개짐 | 페이지를 모델 최대 해상도(긴 변 2576px) 안에서 **가로 띠 3~4장**으로 잘라 보냄 |
| 사진의 원근 왜곡·기울기·그림자·노이즈 | 원근 보정 → 기울기 보정 → 노이즈 제거 → 조명 평탄화 → 대비 보정 (**생성형 AI 업스케일은 사용 안 함**: 흐린 글자를 그럴듯한 다른 글자로 지어내기 때문) |
| AI가 자신 있게 틀림 (3↔8, 1↔7) | **이중 판독**(보정본 vs 원본, 또는 Claude vs CLOVA OCR) → 불일치 지점만 고해상도로 **재판정** → 확신이 없으면 `⟦?값⟧` 표시를 남김 |
| 숫자가 틀려도 겉보기엔 정상 | 양식 규칙 검증: 석차등급 범위, 원점수-성취도 구간, 분포비율 합 100%, 단위수, 세특 글자 수, 문항 번호 누락, 선지 개수·기호 순서, <보기> ㄱㄴㄷ 대응 |
| 원본 PDF에는 이미 정확한 텍스트가 들어 있음 | 텍스트 레이어가 있으면 **OCR 없이 그대로 사용**(정확도 100%). 스캐너가 덧씌운 저품질 OCR 레이어는 걸러냄 |

```
입력(PDF·사진 여러 장)
 ├ 텍스트 레이어 있음 ──────────────────────────────┐
 └ 스캔/사진 → 보정 → 1차 판독(보정본)              │
                    → 2차 판독(원본 or CLOVA)        │
                    → 대조 → 불일치만 재판정          │
                                                    ▼
                         전사문(⟦?⟧ 표시 포함) → 구조화(JSON) → 규칙 검증
                                                    ▼
                         웹 검수 화면: 원본 이미지 ↔ 전사문 나란히, ⟦?⟧ 바로 찾아가기
```

## Word 자동 변환

판독이 끝나면 **Word 파일 2개가 자동으로 만들어집니다.** 웹 화면에서는 기본 설정이 "완료되면 자동 다운로드"이므로, 파일을 올리면 끝날 때 바로 받아집니다.

| 파일 | 내용 | 용도 |
|---|---|---|
| `<제목>_전사.docx` | 원문을 쪽 단위로 그대로 옮긴 문서. 표는 실제 Word 표로, ⟦?⟧는 **노란 형광펜**으로 표시 | 원본 보관, 그대로 편집 |
| `<제목>_정리.docx` | 생기부: 성적표(가로 방향, 불확실 칸은 노란색), 세특·창체·행특 / 시험지: 문항 번호·발문·자료 박스(안의 표 포함)·선지. 자동 검증 결과가 부록으로 붙음 | 상담 자료, 변형 문항 작업 |

일반 문서를 빠르게 Word로만 바꾸려면 문서 종류를 **일반 문서(전사만)**, 판독 방식을 **단일(저렴)**로 고르세요. 이 경우 전사본만 만들어집니다.

## 설치

```bash
pip install -r requirements.txt
cp .env.example .env      # ANTHROPIC_API_KEY 입력
```

Python 3.10 이상이 필요합니다. Windows는 `run_web.bat`, Mac/Linux는 `./run_web.sh`로 실행하세요.

## 사용법

### 1) 웹 화면 (권장)

```bash
./run_web.sh            # 또는 Windows: run_web.bat
# 브라우저에서 http://127.0.0.1:8000
```

1. 파일을 끌어다 놓습니다. 여러 장이면 올린 순서대로 이어 붙습니다.
2. 문서 종류(생기부/시험지/일반)와 판독 방식을 고른 뒤 **판독 시작**을 누릅니다.
3. **검증 결과**의 오류와 확인 항목부터 봅니다. 페이지 번호가 빨간색이면 해당 쪽 전체를 다시 보고, 주황색이면 ⟦?⟧ 표시가 있는 쪽입니다.
4. 원본 이미지와 전사문을 나란히 놓고 **다음 ⟦?⟧ 찾기**로 하나씩 고친 뒤 **이 쪽 저장**을 누릅니다.
5. **구조화·검증 다시 실행**을 누르면 고친 내용이 JSON과 검증 결과에 반영됩니다.

### 2) 명령줄

```bash
python -m docread 생기부.pdf --profile saenggibu --title "2학년 학생A" --out out/학생A
python -m docread p1.jpg p2.jpg p3.jpg --profile exam              # 시험지 사진 3장
python -m docread 시험지.pdf --profile exam --passes 1             # 단일 판독(저렴)
python -m docread 생기부.pdf --force-ocr                           # 텍스트 레이어 무시
python -m docread --restructure out/학생A                          # 전사문 수정 후 재구조화
```

결과 폴더에는 다음 파일이 생깁니다.

| 파일 | 내용 |
|---|---|
| `<제목>_전사.docx`, `<제목>_정리.docx` | Word 파일 (위 설명 참고) |
| `transcript_clean.md` | 최종 전사문(표시 제거) |
| `transcript.md` | ⟦?⟧ 표시가 포함된 전사문 |
| `saenggibu.json` / `exam.json` | 구조화 결과 (성적 행, 세특, 창체, 행특 / 문항, 자료, 선지) |
| `result.json` | 전체 기록: 쪽별 1·2차 판독 원문, 불일치 판정 근거, 검증 결과, 토큰 사용량 |
| `pages/` | 보정 전후 이미지 |

## 실전 테스트 방법 (정확도를 숫자로 확인하기)

"잘 읽는 것 같다"는 느낌이 아니라 **측정값**으로 판단하세요.

1. 판독이 어려웠던 샘플을 5~10쪽 고릅니다. 생기부 성적표, 세특, 시험지(2단 편집, 그래프, <보기>)를 섞어 주세요.
2. 그 쪽들의 **정답 전사문**을 사람이 직접 만듭니다. 쪽 구분은 `=== 3쪽` 줄로 표시합니다.
3. 판독한 뒤 다음 명령으로 비교합니다.

```bash
python -m docread.evaluate out/학생A 정답.md
# → 문자 정확도 99.6% · 숫자 정확도 99.9% · 오류 중 표시된 비율 85%
```

| 지표 | 의미 | 목표 |
|---|---|---|
| 문자 정확도 | 공백·표 기호를 뺀 글자 기준 | 99.5% 이상 |
| **숫자 정확도** | 등급·점수·평균·표준편차만 따로 비교 | **99.9% 이상** (입결 판단에 직결) |
| 오류 중 표시된 비율 | 실제로 틀린 곳에 ⟦?⟧ 표시가 붙어 있었던 비율 | 높을수록 좋음. 높으면 ⟦?⟧만 검수해도 충분하다는 뜻 |

같은 샘플로 `--passes 1`과 `--passes 2`를 각각 돌려 비교하면, 이중 판독이 비용만큼의 값을 하는지 바로 확인할 수 있습니다.

## 비용 (추정치)

모든 작업은 화면과 명령줄에 **실측 토큰 수와 비용**을 표시합니다. 아래 표는 A4 1쪽 기준 대략치입니다.

| 방식 | 쪽당 추정 비용 | 비고 |
|---|---|---|
| PDF 텍스트 레이어 | 구조화 비용만 | OCR 생략 |
| 단일 판독 | 약 $0.10~0.15 | 띠 3~4장 + 전체 축소본 1장 |
| 이중 판독 + 재판정 | 약 $0.25~0.40 | 불일치가 없으면 재판정 생략 |

생기부 20쪽을 이중 판독하면 약 $5~8입니다. 비용을 줄이려면 다음 방법을 쓰세요.
- 원본 PDF(정부24·나이스 발급본)를 받습니다. 텍스트 레이어가 있으면 OCR이 아예 필요 없습니다.
- 성적표처럼 숫자가 중요한 쪽만 이중 판독하고, 나머지는 `--passes 1`로 판독합니다.
- `.env`에서 `DOCREAD_MODEL=claude-sonnet-5-5`로 바꿉니다. 단가는 절반이지만, 위의 정확도 측정으로 품질이 유지되는지 반드시 확인하세요.

## CLOVA OCR 연동 (선택, 정확도 추가 향상)

2차 판독을 Claude가 아닌 **원리가 다른 엔진**으로 하면, 두 판독이 같은 실수를 할 확률이 더 낮아집니다.
네이버 클라우드 콘솔에서 CLOVA OCR의 General 도메인을 만들고, `.env`에 `CLOVA_OCR_URL`과 `CLOVA_OCR_SECRET`을 넣으면 자동으로 사용됩니다.
> 참고: CLOVA 연동 코드는 공개 API 명세를 기준으로 작성했으며, 실제 키로는 아직 테스트하지 않았습니다.

## 개인정보 주의

- 판독 과정에서 페이지 이미지가 Anthropic API로 전송됩니다(CLOVA를 쓰면 네이버 클라우드에도 전송). **학부모 동의서에 "AI 판독 외부 위탁" 항목을 넣으세요.**
- 전사문에서는 이름·주민번호·주소·전화번호를 `[이름]` 같은 표시로 바꾸도록 지시하지만, **이미지 자체는 가리지 않고 전송됩니다.** 가능하면 인적사항 쪽은 빼고 올리세요.
- 웹앱은 기본적으로 이 컴퓨터에서만 접속됩니다(127.0.0.1). 결과는 `data/` 폴더에 쌓이니 주기적으로 지우세요. `data/`, `out/`, `samples/`는 git에서 제외되어 있습니다.
